# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

HIMS v2 — the Performance & Development module of a Hospital Information Management System for a Philippine hospital. Laravel 13 / PHP 8.3, MySQL 8, server-rendered Blade.

The Laravel app lives in `hims-app/`, not the repo root. Run all commands from `hims-app/`.

## Commands

```bash
composer setup                     # install deps, .env, key, migrate, npm build
composer dev                       # serve + queue worker + pail logs + vite (concurrently)
php artisan serve                  # app alone on :8000
npm run dev                        # vite alone

composer test                      # config:clear then artisan test
php artisan test --filter=test_profile_page_is_displayed
php artisan test tests/Feature/Auth/AuthenticationTest.php

php artisan migrate:fresh --seed   # rebuild DB (seeder prints the login it creates)
vendor/bin/pint                    # formatter
```

Seeded login: `admin@hospital.ph` / `password`.

## Database access pattern

**This app barely uses Eloquent.** `App\Models\User` is the only model; everything else is raw Query Builder (`DB::table('employees')->join(...)`) directly in controllers — 329 `DB::table(` call sites across 14 files (13 domain controllers plus 6 sites in the `Controller` base class). There are no models, policies, observers, or repositories for the 40+ domain tables. Match this style rather than introducing Eloquent models piecemeal.

Consequences to respect when editing:

- **UUIDs are generated in PHP.** All domain PKs are `CHAR(36)` populated with `Str::uuid()` at insert time. Nothing auto-generates them — an insert that omits the PK will fail.
- **`created_at`/`updated_at` must be set manually** (`'created_at' => now(), 'updated_at' => now()`), since Query Builder has no timestamp magic.
- **MySQL-only SQL is embedded in controllers**: `CONCAT()`, `DATE_FORMAT()`, `FIELD(...)` ordering, `whereMonth()`. Migration `..._000030_create_competency_tables` installs MySQL triggers via `DB::unprepared`, and the recognition restore migration creates `v_recognition_leaderboard` for reporting; the recognition wall's core query remains portable so its feature tests run on sqlite.
- **`phpunit.xml` runs tests on sqlite `:memory:`.** The latest verified runs are **359 tests, 338 passed, 21 skipped, 1537 assertions** on the default sqlite connection and **359 tests, 359 passed, 0 skipped, 1605 assertions** against a MySQL scratch database — both figures are given because the difference *is* the point: the 21 skips and the 68 extra assertions are the MySQL-only read paths, and only the second run exercises them. Those paths are explicitly gated (notably `Feature\EmployeeProgressionTest`, `Feature\GapAnalysisFeedbackTest`, and selected `Feature\ReviewAuthorityTest` listings); the portable authorization, privacy, audit, succession, recognition, search, notification, and reporting tests stay in the default sqlite run. Note that the skip count has not moved as the total grew — every test added since has landed on the portable side, so the gated read screens carry no more coverage now than they did then. Follow that split: a new feature test that reaches MySQL-specific SQL or triggers must gate itself the same way, or stay off the raw SQL paths.
- **Never run the suite with `php artisan test --env=testing`.** There is no `.env.testing`, so Laravel falls back to `.env` — where `DB_DATABASE=hims_v2`, the development database — and `RefreshDatabase` on a non-sqlite connection runs `migrate:fresh`, which drops and recreates every table. It has already destroyed `hims_v2` once (2026-08-11; recovered by binlog point-in-time replay). Plain `php artisan test` is safe because `phpunit.xml` pins sqlite `:memory:`. To run against MySQL deliberately, name a **scratch** database on the command line and never `hims_v2`: `DB_CONNECTION=mysql DB_DATABASE=hims_align_check php artisan test`, then drop it. Note that `phpunit.xml`'s `<env>` entries are not `force="true"`, so a shell-exported value wins — which is what makes the scratch override work, and also why a stale export is dangerous.
- **A whole class does not have to be MySQL-gated when only some of its tests are.** `Feature\ReviewAuthorityTest` is the model: the review *authority* rules are portable Query Builder, but every review *listing* selects `CONCAT(first_name,' ',last_name)`, which sqlite has no function for. So it carries a private `requiresMysql()` helper called from the seven tests that drive a read screen — the review listing, the review detail page, the scoring form and the dashboard tile — rather than a `setUp()` gate, which keeps the other twenty-nine, where the rules actually live, in the default sqlite run. Those seven plus `Feature\EmployeeProgressionTest` (5) and `Feature\GapAnalysisFeedbackTest` (9, whole-class gates) are the entire 21. **They are the reason to run the suite against MySQL before believing it**: `php artisan test` alone reports them as skips, so a regression in a read screen looks exactly like a green run.
- **Portable SQL is not the same as correct SQL, and sqlite will not tell you.** The accreditation report shipped with `jci_standard_code` selected off `competencies`, where the column does not exist; every sqlite test passed because none of them put a competency row in front of the query, so the failing branch never ran. It surfaced only as a MySQL 500. The tag lives on **`competency_categories`** — one join above the competency — and the same join is needed in `ComplianceController::competencyRollup()` and `SuccessionController::readinessEvidence()`. When a query joins a column you have not personally read out of the migration, check the migration.
- **The same trap fires through a Blade property, and there it is a `SELECT *` that hides it.** `employees/progression.blade.php` printed `$cr->credential_name` from a `select *` on `employee_credentials`, where the column is **`credential_type`** — so nothing in the query complained and the page 500'd inside the `@foreach`, but only for an employee who actually had a credential. All four `EmployeeProgressionTest` cases that existed then seeded employees with none, so the loop body had never executed in a test and the run stayed green — the fifth case, `test_progression_view_renders_credentials()`, was added to enter it, which is why the breakdown above counts five. **A `@foreach` whose body a test never enters is untested code**, whatever the coverage of the surrounding page: when adding a table to a view, seed at least one row of it. The credential display name is `credential_type` everywhere — `employees/show`, `competency/credentials/index`, `competency/gap-analysis/employee` and all four dashboard partials agreed; the progression page was the lone outlier.

## Module layout

The HR-module navigation contains Performance, Competency, AI Gap Analysis, Learning (including the former Training and Compliance surfaces), Recognition, and Succession, plus Employees/departments/users administration. `LearningController` and `ComplianceController` remain separate handlers, but their canonical routes share the `learning.*` prefix and their views live under `resources/views/learning/`. A small `/compliance/...` route group remains only as backward-compatible aliases for bookmarks, integrations, and older tests. All routes sit behind `['auth','verified']`, most with an additional `role:` middleware — see "Docs vs. implementation" below.

**Create screens are modals rather than GET pages** for cycles, competency assessments, credentials, domains, courses, pathways, CPD, required-training assignments, renewal rules, training sessions and venues, recognition posts and badges; training feedback is likewise a modal on the session page. The old controller create methods and Blade pages were removed where they existed. **The dropdown/checklist data they used to load moved into host-page methods**, which is why pages often select data the visible page body itself does not use. `LearningController::taggableCompetencies()` is the shared query behind the course create/edit modals and the course show page's tagging list — adding another caller means calling that helper, not writing the join again. Deleting a page like this is only safe because `AiActionRegistry` keys point at `.store` routes and never `.create`; keep it that way.

**Learning and compliance are two controller halves of one visible Learning module, split by whose question they answer.** `LearningController` owns the catalogue, CPD and pathways; `ComplianceController` owns required training, renewal rules/risk, accreditation and account coverage. The sidebar has one **Learning** item, with canonical `learning.*` routes and eight tabs: Overview, Required Training, Renewals, My CPD, Pathways, Sessions, Venues and Reports. Only Required Training, Renewals and Reports are gated (on `view-compliance`); Sessions and Venues are the former Training module's two screens and every role sees them. `learning.cycles.mine` (`GET /learning/my-cycles`) is served by `ComplianceController::myCycles()` because it reads renewal machinery but answers the employee's own question. **Course self-enrolment has been removed**: every new `course_enrollments` row is created through Required Training and carries an `assignment_id`; null now denotes legacy pre-removal rows only. Training sessions still allow self-registration.

**Required Training is multi-subject and modal-first.** `learning.assignments.store` accepts `subjects[]` containing `course:<uuid>` and `session:<uuid>` values; the modal presents separate searchable checkbox lists and may mix both types in one submission. `TrainingAssignmentService::assignMany()` creates one `training_assignments` row per subject inside one transaction because each subject needs its own roster and completion rate. The Required Training table's outstanding/overdue badge and Roster button open a filtered in-page modal; `learning.assignments.show` remains a valid deep link and the `/compliance/...` names remain compatibility aliases. **Scope nuance:** `storeAssignment()` access-checks a single-employee target, but department/role/all targets expand globally from active employees; roster visibility is still filtered afterwards. Do not describe all supervisor assignment targets as direct-report-only unless that write path is tightened.

**Course completion is the one write both halves depend on**, and it lives on the Learning side: `LearningController::completeEnrollment()` / `reopenEnrollment()` (routes `learning.enrollments.complete` / `.reopen`) are what set `course_enrollments.status = 'completed'`. Until they existed nothing did, so every course assignment's compliance rate was pinned at 0% and `cpd_hours_earned` was never populated. Completing credits a `verified` `cpd_records` row worth the course's `cpd_hours`, which is how a completion feeds `RenewalCycleService::attainedHours()`. Recording a completion is supervisor-and-up (`record-completion` gate + `role:admin,hr_manager,supervisor` on the route, with `authorizeEmployeeAccess()` holding a supervisor to their **own direct reports** since the scope rewrite) because it is a statement about a person — nobody self-certifies, mirroring session check-in. Reopening is narrower still (`manage-learning`, so admin/HR only) because it withdraws evidence and deletes the CPD row. **Sessions are not completed this way** — `training.sessions.checkin` remains their only mechanism, so a session never has two places recording the same fact.

**Reviews are the exception to the modal rule** — `performance.reviews.create` is still a real GET screen with a controller method, because the employee dropdown is itself an authorization statement (it lists only who the actor may legitimately review) and it grows an exception-reason field when the chosen employee is out of chain. That is more than a modal should decide.

Departments are handled by **closures inline in `routes/web.php`**, not a controller. (`web.php` used to carry a `use App\Http\Controllers\DepartmentController;` import for a class that does not exist; it has been removed, so the import block now lists only classes that resolve.)

## Views

Two layout systems coexist:

- `layouts/hims.blade.php` — the real app shell, extended by 48 current Blade views. Hand-written sidebar/panel JS inline, plus a `window.onerror` hook that POSTs to the `log-error` route.
- Breeze's `x-app-layout` / `layouts/app.blade.php` — only `profile/edit` still uses it.

Styling is **`public/css/hims.css` (1506 lines, hand-authored, served directly)**. Tailwind and Vite are installed and configured but `resources/css/app.css` is 3 lines — the domain UI does not go through the build. Add styles to `hims.css` unless deliberately migrating a view.

**Because it is served outside the build, its URL has to be content-keyed by hand, and that is a correctness rule rather than a performance one.** A Vite bundle's filename contains its own hash, so a new build is a new URL; `hims.css` has one constant URL forever, the deployed origin sends `Cache-Control: max-age=14400`, and Cloudflare sits in front — so for four hours after a release the browser *and* the shared edge cache serve the previous stylesheet against the new container's HTML. The page does not go unstyled, which is what makes it hard to spot: everything that existed before the release still looks right, and only markup whose classes are new renders bare. That is exactly how beta.3's `.hims-tabs`, `.hims-modal`, `.hims-checklist` and `#ai-rail` arrived broken in production — the Learning and Recognition tab strips as underlined links, and the AI rail (no `position: fixed` reaching it) laid out at the foot of the document, so `openRail()`'s closing `input.focus()` scrolled to the bottom of the page instead of opening a panel. Three unrelated-looking bug reports, one stale file.

So both unbuilt static assets append their own content hash — `substr(md5_file($path), 0, 8)` at `partials/app-css.blade.php:31` and `partials/favicon.blade.php:27`, each guarded by `is_file()` so a checkout missing the asset renders rather than throwing. **Load the stylesheet only via `@include('partials.app-css')`; a bare `asset('css/hims.css')` anywhere is the regression**, and `Unit\AssetCacheBustingContractTest` fails on it — it also pins the hash to the running file's actual md5 (a hardcoded `?v=2` looks identical in the HTML and dies the first time someone edits the CSS without bumping it) and checks that all four standalone `<head>`s — the app shell plus the three auth pages, which carry their own `<!DOCTYPE>` — come through the partial. The Breeze layouts are deliberately out of scope: they load `app.css` through `@vite`, which hashes filenames itself.

### Tables

`.hims-table` is the shared table style used by the current table views. Two rules, both regression-tested by `Unit\TableAlignmentContractTest`:

- **`.hims-table th` sets its own `text-align: left`; never leave it to the user agent.** The browser default is `center` for `th` and `left` for `td`, and Bootstrap's reboot papers over the mismatch with `th { text-align: inherit }` — **HIMS loads no Bootstrap CSS, only the bootstrap-icons font**, so nothing supplied that. The declaration was simply absent, and every header in the app sat centred above left-aligned data. One declaration in `hims.css` fixes the shared table style; the test asserts it is present *and* that no later rule (the responsive blocks restyle `.hims-table th` padding) re-centres it.
- **A column that is not left-aligned says so on both its `th` and its `td`s, using the shared classes** — `.text-center` / `.text-end` / `.text-start` (`hims.css:904-906`, all `!important`). Note `.text-right` and `.text-nowrap` do **not** exist; nothing uses them. Inline `style="text-align:…"` on a table cell is banned and asserted against: it is invisible to a class scan, so one inline cell would silently exempt its column from the pairing check. `colspan` cells are exempt — an empty-state row centred across the table belongs to no column, so it has no header to agree with.

The pairing check is **per file, comparing the set of classes used on `th`s against the set used on `td`s** — not per column index. Matching a header to its cells by index means counting through `@can`-wrapped headers, `colspan`s and conditional columns, and a parser that fragile fails on edits that are fine. Per-column verification is a browser job, not a regex job, and it was done once as a throwaway headed-Chrome harness — since deleted, so there is nothing to re-run — comparing each `th`'s computed `text-align` against its column's `td`s by `cellIndex` across 34 pages (46 rendered tables, 242 header cells, 0 mismatches). If you rebuild it: Chrome reports the initial value as `start`, so normalise `start`→`left` and `end`→`right` before comparing, or every unstyled column reads as a mismatch.

Only one table deviates from left on a data column: `employees/progression.blade.php` centres its fixed-width bare-number columns (Required / Current / Gap / Progress / CPD / Hours), headers included. Five others right-align only a trailing action column, `.text-end` on the `th` and its `td`s alike — `competency/gap-analysis/index`, `learning/index`, `learning/courses/show`, `learning/assignments/show` and `learning/assignments/_roster-modals`. Numerics were deliberately **not** right-aligned app-wide — compound cells like the accreditation report's `count + badges` and `competency/index`'s `3/5` + gap chip make "numeric" un-decidable, and re-deciding it would be a redesign.

### Alerts

`.hims-alert` is the flash/inline banner. Two contract rules, both regression-tested by `Unit\AlertDismissContractTest`:

- **Auto-dismiss is opt-in, not the default.** The layout's timer only removes an alert carrying `data-auto-dismiss`. Flash confirmations opt in; an alert that explains *why an action was refused* must not, or the explanation vanishes while the user is still reading the screen it applies to.
- **The banner is prose, not a flex row.** Its content flows as text so a long sentence wraps inside the banner instead of stretching it into a single line.

### Modals

**Creating or editing a compact record happens in a modal on the page it belongs to, not on a separate GET page.** The shared modal system now covers cycle create/edit, competency assessments/credentials/domains, course create/edit, pathways, CPD, required-training assignment and roster drill-downs, renewal rules, training sessions/venues/feedback, and recognition posts/badges. All use the same `.hims-modal-backdrop` / `.hims-modal` pair (z-index 1200 to clear the topbar and its dropdowns). The backdrop is deliberately `transparent` — it is a full-viewport click target for dismissal, not a scrim — so the panel carries its own separation via a `--hims-primary` border and a heavier shadow.

| Partial | Modal id | Hosted on | Needs |
|---|---|---|---|
| `performance/cycles/_create-modal` | `cycleCreateModal` | `performance/index`, `performance/cycles/show` | — |
| `performance/cycles/_edit-modal` | `cycleModal` | same two | per-row `data-*` |
| `competency/assessments/_create-modal` | `assessmentCreateModal` | `competency/index` | `$employees`, `$competencies` |
| `competency/credentials/_create-modal` | `credentialCreateModal` | `competency/index`, `competency/credentials/index` | `$employees` |
| `learning/courses/_create-modal` | `courseCreateModal` | `learning/index` | `$competencies` |
| `learning/courses/_edit-modal` | `courseEditModal` | `learning/index` | per-row course values + tags |
| `learning/pathways/_create-modal` | `pathwayCreateModal` | `learning/index`, `learning/pathways/index` | `$roles` |
| `learning/assignments/_create-modal` | `assignmentCreateModal` | `learning/assignments/index` | courses, sessions, targets |
| `learning/assignments/_roster-modals` | one id per assignment | `learning/assignments/index` | visible roster per assignment |

Five contract rules hold the set together:

- **Modal markup is `@push`ed to the layout's `@stack('modals')`, which sits outside `<main>`.** Every partial wraps *only* its `.hims-modal-backdrop` in `@push('modals')`; the `@include('partials.modal-js')` and any auto-open `@push('scripts')` block stay outside the push. This is not tidiness — the content wrapper inside `<main>` carries `.animate-in`, whose `fadeInUp` keyframes end on `transform: translateY(0)` and are held there by `animation-fill-mode: forwards`. **Any transform other than `none` makes an element the containing block for its `position: fixed` descendants**, so a backdrop rendered inside that wrapper resolved `inset: 0` against the full page content box and centred the panel in the middle of the *page* — on a long page (Competency), far below the fold. Rendering as a direct child of `<body>` is what keeps "fixed" meaning fixed. The CSS was always correct and was not touched; `margin: auto` on `.hims-modal` centres both axes inside the flex backdrop, and `align-items: flex-start` + `overflow-y: auto` let a modal taller than the viewport scroll instead of clipping. A new modal that forgets the push will look fine on short pages and drift on long ones.
- **`partials/modal-js.blade.php` is the only modal controller.** It is `@once`-guarded and `@push`es to `@stack('scripts')`, so a page can `@include` it per modal and still ship one copy. It defines `window.himsModal.open(id)` / `.close(id)`, then listens on `document` for `[data-modal-open="<id>"]` and `[data-modal-dismiss]` — **delegated**, which is what lets markup rendered later still work and lets two modals share one page. Opening also locks body scroll and remembers the trigger so focus returns to it on close. **Markup declares intent via `data-modal-open`; no page writes its own open/close JS.** Animation is two-phase: `.open` sets `display`, then `.shown` on the next `requestAnimationFrame` drives the transition, so a synchronous assertion right after a click sees `open` without `shown` — that is correct, not a bug.
- **Validation failures reopen the right modal.** Every form carries a hidden `_modal` field naming its own id; the partial reopens itself when `$errors->any() && old('_modal') === '<its id>'`. Without this a page hosting two modals could not tell which one to bring back.
- **`?new=<thing>` deep-links open a modal on page load** (`cycle`, `assessment`, `credential`, `domain`, `course`, `pathway`, `cpd`, `assignment`, `rule`, `session`, `venue`, `post`, `badge`); `?feedback=1` opens training feedback. Dashboard quick actions and cross-module prompts use these, which is what kept them one click after GET create pages were deleted.
- **The edit modal is one form, re-pointed.** Buttons carry `data-cycle-edit` plus the row's values in `data-*`; a delegated handler rewrites `form.action` and fills the fields. A table of twenty cycles still ships one `<form>`. `updateCycle()` redirects to `performance.index`, not the cycle — the modal is opened from whichever page the user was already on, so landing them elsewhere reads as a redirect they did not ask for.

### Checkbox lists

Multi-select is a **`.hims-checklist`** — a scrolling box of `<label><input type="checkbox" name="x[]"></label>` rows — never `<select multiple>`. The Ctrl/Cmd-click hint it replaced was the specific thing users could not discover. It is used for course competency tagging, pathway target roles, and the two searchable Required Training subject lists (courses and upcoming sessions). The assignment lists post to one `subjects[]` array with type-prefixed values.

`partials/checklist-js.blade.php` (same `@once` + `@push` shape) adds optional filtering: an `<input data-checklist-filter="<list id>">` above the list hides non-matching rows and reveals `[data-checklist-empty]` when nothing matches. **It toggles `display` on the `label` only and never touches `checked`**, so a box ticked before filtering is still ticked — and still submitted — after. Lists small enough not to need it (target roles, 9 rows) omit the filter input and the include.

`.hims-link-button` is a `<button>` styled to read as the inline link it replaced, for empty-state sentences that now open a modal instead of navigating.

### List filters

A filter on a list or card is a **`<form method="GET">` wrapping a `<select onchange="this.form.submit()">`**, with `@selected(...)` reading the current value back off the request so the control still shows the chosen option after the reload. No Apply button — there is nothing to hunt for, and the URL stays shareable and survives a refresh. `succession/index` (position) and `competency/index` (the Department Skills Gap Matrix) both use this shape; `competency/gap-analysis` still has an explicit **Filter** button and has not been converted.

The gap matrix filter is worth one note: **competencies are department-agnostic** — there is no `competencies.department_id` — so `?department_id=` narrows which *assessments* are averaged, by joining `competency_assessments` → `employees` and filtering on the employee's department. The query is an **inner** join on `competency_assessments`, not a left join: a competency nobody has been assessed on has `AVG(...) = NULL`, which the view's `?? 0` turned into a green "Met" badge on an untested skill. Filtering to one department makes that the common case rather than the rare one, so never-assessed competencies are now excluded from the matrix entirely.

## Services

- **Global Search** — `GlobalSearchController` serves authenticated `GET /search?q=...` requests from an explicit source allow-list. It searches navigation, employee/development records, performance, competency, learning, training, recognition, succession, administration, and the caller's own AI sessions. Every source applies its owning module's scope before matching; the endpoint returns destinations, not authorization grants. Do not replace it with table discovery or a deny-list.

  **A search result's `#fragment` is a contract with a Blade view, and getting it wrong takes the page down rather than just missing the scroll.** The controller builds row-level destinations by appending `'#cpd-'`-style prefixes to a route, so some view must render `id="cpd-{{ $cpd->cpd_id }}"` — and it must render it **inside the loop that binds that variable**. Put the anchor on the `<thead>` row or anywhere above the `@forelse`, and the loop variable is not in scope: Blade compiles `{{ $cpd->cpd_id }}` to a bare PHP variable read, so an undefined variable there is a fatal `ErrorException` and a **500 on every visit**, not an empty string. That is precisely how three pages broke at once — `learning/cpd/index`, `competency/domains/show` and `performance/show`, each with the anchor one loop too high. `Unit\SearchAnchorContractTest` now scrapes the fragment prefixes straight out of `GlobalSearchController`, requires each one to have a view that renders it, and walks upward from every anchor site to the nearest `@foreach`/`@forelse` to assert the id interpolates *that* loop's variable. Its third test is a floor (≥8 known anchors) so a regex that silently stops matching cannot pass as a clean scan. **Adding a row-level search destination means adding the anchor to the row, and the test tells you if you put it anywhere else.**
- **Notification service** — `NotificationService::feedFor()` returns the caller's twelve most recent read/unread rows with presentation metadata and an access-aware destination. `markRead()` and `markAllRead()` are recipient-scoped. The shell keeps read rows visible, changes only their emphasis/count, and marks one row before navigating. A credential focus link is emitted only when the recipient can see the subject employee; an out-of-chain department-head escalation falls back to the module page.
- **AI layer** — provider-agnostic. Consumers (`AiController`, `CompetencyGapAnalysisService`) depend on the `App\Contracts\AiProvider` contract (`ask(string $prompt, array $history = [], ?string $scope = null): string` — `$history` replays earlier turns, `$scope` carries the RBAC fragment), resolved by `App\Services\Ai\AiManager` from the `services.ai` config and bound in `AppServiceProvider::register()`. `AI_PROVIDER` (`gemini`|`openai`|`anthropic`|`compatible`) picks the active driver; **Gemini is the default** so the existing `GEMINI_API_KEY` keeps working. Drivers live in `app/Services/Ai/` (`GeminiProvider`, `OpenAiProvider` — also serves OpenAI-compatible hosts like Groq/DeepSeek/xAI via `AI_COMPATIBLE_*`, `AnthropicProvider`), all raw-HTTP over `Http::` and all extending `AbstractAiProvider`. **Failure contract:** `ask()` never throws for an API/config problem — it returns a `⚠️`-prefixed string, which `CompetencyGapAnalysisService::parseAiJson()` treats as "AI unavailable". The active model is env-configurable per provider (`GEMINI_MODEL`, `OPENAI_MODEL`, `ANTHROPIC_MODEL`, `AI_COMPATIBLE_MODEL`); the **fallback chains are not** — they are hardcoded literal arrays in `config/services.php`, and only `gemini` and `anthropic` define one at all (`openai` and `compatible` have no `fallback_models` key, so a bad model there is a hard failure). The old concrete `GeminiService` was removed; its three unused helpers (`checkBias`/`generateQuizQuestions`/`analyzeSentiment`, with the `Str::limit` import fixed) now live on `AbstractAiProvider` and remain unreferenced.
- **AI action services** — `AiActionRegistry` (30-action catalogue derived from route middleware), `AiActionPlanner` (classification), `AiEntityResolver` (name → UUID), `AiActionExecutor` (controller invocation + audit). `AiController::query()` drives the pipeline: verb pre-filter → planner → registry (role check) → resolver → executor (prefill + invoke + audit). See `HIMS_SYSTEM_DOCUMENTATION.md` §5.1.
- **Compliance services** — `TrainingAssignmentService` (fan a course or session out to an employee / department / role / everyone, then measure completion) and `RenewalCycleService` (open and settle renewal cycles, count verified CPD inside the window, rate the risk). Both key off `employee_id` only: **nothing in the compliance layer needs a `users` row**, which is the point — an employee tracked by proxy is still governed by it. `RenewalCycleService::atRisk()` takes a `?callable $scope` so the caller can hand in `Controller::scopeToVisibleEmployees()`; attained hours are summed from `cpd_records` on every read rather than stored on the cycle, because verification lands days after the log and a stored total would be stale.
- **Date-boundary helpers** — three small `App\Support` classes, all deriving state from a date rather than trusting a stored column, and all comparing `Y-m-d` **strings** (not Carbon) so the SQL stays portable to sqlite. `CredentialStatus` is the one definition of "expired" / "expiring" (`WINDOW_DAYS = 30`); `CycleStatus` is the one definition of a review cycle having ended; `ReviewStatus` decides whether a review is still editable and **forwards to `CycleStatus`** for the date test so the badge and the lock cannot drift apart. Bind their `today()` / `windowEnd()` as query parameters rather than interpolating — that is what keeps `credentialRollup()` and `CycleStatus::whereNotEnded()` sqlite-safe.
- **`App\Support\KpiWeighting`** — the one definition of how a KPI's weight becomes influence over a review's score, in the same shape as the three above (`final class`, static, no DB, no Carbon). **A weight means nothing on its own**: `kpi_library.weight` is a `decimal(3,2)` that only acquires meaning next to the other weights on the same review, because `overall_score` is a weighted mean that divides by their total. So the screens print the quotient — `shares()` answers "how much of the final score does this KPI decide?" — and `recalculateReviewTotals()` gets its `weight ?: 1` rule from `effectiveWeight()`, so a KPI cannot be *shown* as deciding 13% of a score that was *calculated* as though it decided something else. Two traps it exists to close: **the denominator is the rated rows, not the attached ones** (an unrated KPI is absent from the roll-up, not a zero — `cleanScore()` nulls it, its weight leaves the denominator, and the rest grow to fill the gap), and **`displayShares()` is what a screen must call, never `shares()`** — a column of percentages is read down and added up, so the integers are apportioned by largest remainder to total exactly 100 rather than each rounding alone. Independent rounding really does overshoot on live data: both seeded reviews summed to 102%.
- **`App\Support\ReviewFeedback`** — the one definition of "what has been written about this employee in their performance reviews", same shape as the four above (`final class`, static, no Carbon) with **one deliberate exception: `promptLines()` reads the database**, because the two switches that decide what may leave the hospital for an AI provider live in `system_settings` and a prompt-builder that ignored them would be the leak. It exists because a review's three free-text fields — `performance_reviews.strengths_text`, `.improvements_text` and every `review_kpi_scores.comments` note — were all being **selected** by `CompetencyGapAnalysisService::performanceSignal()` and then dropped before the prompt heredoc, so the model was asked for `evidence`, `root_causes` and `strengths_to_leverage` while holding three numbers and a cycle name. Three rules: **`group()` feeds both the page and the prompt** (`competency/gap-analysis/employee.blade.php` iterates the array `promptLines()` renders, so a comment cannot reach one consumer without the other — that drift *was* the bug); **only the prompt is truncated** (`MAX_COMMENT_CHARS = 300` plus a `\s+`→space collapse, because a dozen KPIs × 1000 chars × 3 cycles is a five-figure paste — the screen shows the full text); and **a review with nothing written on it is kept, not filtered** — a cycle that passed with nothing typed is itself a finding, and `promptLines()` states the absence in words rather than emitting an empty section a model would fill in. `performanceSignal()` queries **every** comment across the three cycles, not just the weak-KPI ones (praise is evidence), and selects **`supervisor_score`**, not `weighted_score` — identical values today, but only one of them means what the line says. Two traps for anyone editing it: **`strengths_text`/`improvements_text` are selected but deliberately not returned** as keys of their own (`group()` reads them off the rows and carries them per cycle, so a top-level copy would be a second latest-cycle-only definition of the same fact — but drop them from the `select()` and the narrative empties silently), and **each comment is rendered exactly once per page.** The weak-KPI comment is a strict subset of the feedback card's — weak KPIs come from the latest review, the card covers all three cycles including it — so `rks.comments` is *not* selected by the weak-KPI query and the Weakest KPIs card stays a score list. `formatScore()` is public because the view renders the same numbers the prompt does.
- **`system_settings` is the AI data-sharing switchboard, and it fails safe.** A tiny key/value table (live, queried, and previously undocumented) holding exactly two keys, written by `UserController::updateAiSettings()` from the user-administration screen and read by `ReviewFeedback::promptLines()`. `ai_include_comments = '0'` stops written review comments reaching the provider at all — `promptLines()` returns a single sentence saying so instead of the feedback, so the model is told the text was withheld rather than left to infer it was never written. `ai_redact_names` (anything other than `'0'` counts as on) runs `redactPii()` over every strength, improvement and KPI note, blanking the subject's own name parts longer than two characters and any `Patient`/`Pt.`-prefixed identifier. **The read is wrapped in `try`/`catch` whose handler sets `$redactNames = true`** — so a missing table, a migration mid-flight or any query error redacts rather than opens up. Preserve that default in any edit: the failure mode of the opposite choice is patient data in a third-party prompt.
- **`config('app.timezone')` is `Asia/Manila`, and that is an authorization setting, not a display one.** All three date helpers above ask "has this date passed?" against `now()->toDateString()`. Under the stock UTC default that question answered "no" for the first eight hours of every Philippine day, so a cycle that ended yesterday stayed scoreable until 8am and a credential expiring today read as current. `Unit\CycleStatusTest::test_the_app_clock_is_the_hospital_clock` pins it; `phpunit.xml` deliberately does **not** override the timezone, so that assertion is live in the suite.
- **There is no Zapier integration.** `ZapierService` was deleted in `3e121d5`; nothing in `app/`, `routes/` or `resources/` mentions it. All that survives is the unread `'zapier'` block at `config/services.php:102`, whose webhook URLs are blank in `.env` — config with no reader, not a wired-up feature. Do not resurrect it from this line.

## Docs vs. implementation

`HIMS_ARCHITECTURE_AND_SECURITY.md`, `HIMS_SYSTEM_DOCUMENTATION.md`, and `HIMS_USER_GUIDE.md` were stripped to as-built state — they now describe only what the code does. Keep them that way (see the docs rule in the user's memory); anything unbuilt belongs in the patch/release notes, not in these three.

Still **not implemented in app code**: tamper-proof audit trail observers (hash chaining), TOTP MFA, Redis caching, the `notifications` queue, and any REST API (no `routes/api.php`, no Sanctum/Passport). Field-level encryption is limited to `employees.phone` and `employee_credentials.credential_number`, using Laravel `Crypt::encryptString()` / `decryptString()`; other domain fields remain database plaintext. The ten unreferenced placeholder tables this file used to list — `course_modules`, `credential_types`, `permissions`, `quiz_attempts`, `quiz_questions`, `role_permissions`, `succession_reviews`, `system_users`, `training_test_results`, `training_tests` — have been **dropped**, and are absent from the live schema (verified: 51 tables + 1 view, 30 applied migration rows). The drop is done by exactly one migration, `2026_08_14_000002_drop_unused_legacy_tables`; **every owning create-migration still creates them** (`system_users` in `..._000010`, `course_modules`/`quiz_*` in `..._000040`, `training_test*` in `..._000050`, `succession_reviews` in `..._000060`, `permissions`/`role_permissions` in `..._000080`, `credential_types` in `..._000130`) — the `dropIfExists` calls in those files are their `down()` methods. So a fresh `migrate` creates all ten and then drops them, which is why the schema is clean but the create code is still there to read. Nothing queries them; the only two textual matches left in `app/` are the word "permissions" in a search keyword string and a comment in `TrainingAssignmentService` noting `course_modules` is dead. **Do not resurrect them from this list** — if a feature needs modules or quizzes, that is a new migration. (`notifications`, `credential_alert_log`, `course_competencies` and `audit_trails` were once on the unreferenced list and are not: all four are live and queried.)

`audit_trails` is written selectively by `App\Support\AuditTrail::record()` across employee and user administration, competency and credential changes, performance review/cycle/response events, learning/compliance and training-assignment actions, succession changes, recognition moderation, and AI-executed writes. **Audit coverage is deliberately partial**: ordinary reads and many ordinary UI edits are not tracked, and there is no hash chaining. The HR/Admin-only `/audit/history` endpoint exposes the recorded rows; do not read the table as a complete history.

**Authorization is real but module-specific.** `AppServiceProvider::registerGates()` defines **20 Gates**, and `EnsureUserHasRole` is aliased as `role` in `bootstrap/app.php` and applied per-route in `web.php` — route-level RBAC works. Employee, performance, gap-analysis, learning/compliance, and succession flows apply reporting-line or module-specific record checks. Succession limits supervisors to relevant direct-report candidates and positions, then redacts performance/potential scores, 9-box label, readiness, mentor, and candidate status; HR/Admin retain the confidential fields. Recognition uses participant/moderator audience checks for private posts. Verify against the owning controller before assuming a control covers a module.

**Dashboard scope is mixed by design.** A supervisor's core figures, team list, hotspots, and recent reviews are direct-report scoped; credential alerts remain department-scoped; upcoming training sessions are hospital-wide. Do not describe the dashboard as having one universal row filter.

**`scopeToVisibleEmployees()` is a reporting-line filter, not a department filter.** A supervisor sees the rows where `employees.supervisor_id` equals their own linked `employee_id`, plus their own; admin and HR still see everything. It used to match on `department_id`, and the rewrite changed behaviour in every module that calls it — the compliance at-risk list and course-completion authority narrowed along with performance, which is why three `ComplianceTest` fixtures had to start seeding a `supervisor_id`. **A test whose subject merely shares a department with the actor is now the negative case.** The `$departmentColumn` parameter survives for call-site compatibility and is no longer read; the supervisor column is derived by `str_replace('employee_id', 'supervisor_id', $employeeColumn)`, which assumes the aliased table is `employees` — every current call site passes the default `e.employee_id`.

**Performance review authority is identity-based, and no role is exempt.** Reviewer legitimacy is `employees.supervisor_id`, not role and not department: admin and HR have **no blanket review access**. `reviewer_id === employee_id` is refused at both create and score — **there is no self-review and no peer review**; migration `..._000170` dropped `self_score`/`peer_score`, deleted the `reviews.contribute` route, and purged every existing review row. A review has exactly one voice, `supervisor_score`, written by the account that owns it. Admin/HR reach outside the chain only through a logged exception path, valid on exactly four bases — `no_supervisor`, `supervisor_unavailable` (assigned supervisor is `on_leave`/`suspended`/`resigned`), `supervisor_is_subject`, `supervisor_account_unavailable` (the recorded supervisor has no linked Supervisor/HR Manager/Admin account) — each requiring a typed reason, stamped onto `performance_reviews.is_exception_review` / `exception_basis` / `exception_reason`, badged in the UI and written to `audit_trails` as `review_exception`. **`(employee_id, cycle_id, reviewer_id)` is unique** (`pr_employee_cycle_reviewer_unique`) — `review_type` is deliberately *not* in the key, so one reviewer gets one review per person per cycle and cannot open a second by relabelling it; a repeat create redirects to the existing review's score screen instead of inserting.

**Employees can respond to a finished review without changing its scores.** The subject may submit `employee_response` after the reviewer marks the review finished; acknowledgement is available only once the cycle is completed. Submission and acknowledgement timestamps are stored separately and audited as `review_employee_response` or `review_acknowledged`; acknowledging locks the response permanently while reviewer scores remain the source of record.

Two details there are load-bearing:

- **A review's editability is derived from its cycle's `end_date`, never from a stored status column.** `ReviewStatus` reports `completed` — and `scoreReview()`/`saveScores()` refuse the write — the day after `review_cycles.end_date`, with a strict `<` so a cycle ending *today* is open all day. Only `draft` and `finished` are settable by hand and both stay editable; `completed` is final and is nobody's to set. This is deliberately **not** a nightly job: an authorization rule that depends on `schedule:run` being wired is one that fails open on any box where it is not. The cycle badge derives the same way through `CycleStatus`, and `storeReview()` refuses to open a review in an ended cycle — otherwise you could create a review born frozen, editable by nobody.
- **The cost of deriving it: `performance_reviews.status` only ever holds `draft` or `finished`, so any query that filters the column alone silently misses the third state.** The dashboard's Pending Reviews tile shipped as `whereNotIn('status', ['completed'])` — a filter that excluded nothing once nothing wrote `completed`, leaving every frozen review in every ended cycle on the tile as outstanding work while the review screen showed it Completed and refused edits. Both tiles now join `review_cycles` and go through `CycleStatus::whereNotEnded()`. **A new read that wants "open reviews" must join the cycle**; there is no shortcut through the column, and sqlite will not warn you because the tile is MySQL-gated.
- **These checks are private controller methods, not Gates.** A Gate closure receives only `$user`, and every rule here needs the review row — who the subject's supervisor is, which cycle it belongs to, whether that cycle has ended. None of that is answerable from the user alone.

**The two roll-ups are different numbers and the screens now say which is which.** `supervisor_rating` is the plain mean of the KPI ratings; `overall_score` is the same ratings weighted by `kpi_library.weight`. They were labelled "Supervisor Rating" and "Final Score" — two names that read as synonyms — beside a per-KPI **Weighted** column that printed `supervisor_score` verbatim under a heading claiming a weighting it never applied (identical on all 24 live rows, because `saveScores()` writes `weighted_score` as a straight copy). The column is gone from both `performance/show` and `performance/reviews/score`; the labels are now "Average of KPI ratings" and "Final Score / weighted by KPI importance", with a sentence saying why they differ and which one HIMS quotes. The per-KPI cell that replaced it is `KpiWeighting::displayShares()`.

**`review_kpi_scores.weighted_score` is still written and still read — only its display went.** `saveScores()` populates it and `CompetencyGapAnalysisService` plus `competency/gap-analysis/employee` read it, so the column stays. What was removed is the review screens' *presentation* of it, and its entry in `show()`'s named select, which nothing read once the column was dropped from the table — a selected column nothing reads is how the last two stale-column 500s started.
`system_users` (the docs' account table) is dead; real auth uses Laravel's `users` table, extended with `role` and a nullable `employee_id` FK by migration `..._000095`.

**Recognition is named and audience-controlled.** `is_public` defaults to `true`, so approved public posts appear on the wall; private posts remain visible only to their named sender and recipient plus HR/Admin moderators. The same audience check protects private comments and reactions. Self-recognition is refused, sender and recipient remain identifiable in both modes, and moderation/notifications/audit history remain active.
