# AI Sidebar Upgrade — Implementation Plan

## Verdict

**High-risk, and mostly not for the reason the request implies.** Both headline features already exist end to end: `ai_chat_sessions` is a live table with eight routes and five controller methods behind it, and multi-turn replay is threaded through `AiProvider::ask($prompt, $history, $scope)` into all three drivers — so the naive plan (new sessions table, "thread history into the provider") is a duplicate migration that aborts `migrate:fresh` mid-run and a no-op respectively. What remains is a UI rebuild against a shell that has no wrapper element, no flex/grid, and exactly one push variable with two consumers, plus a set of latent memory defects that this change promotes from dormant to load-bearing. Four blockers, ten high-severity risks; the memory kill switch (`AI_HISTORY_TURNS=0`) currently does the opposite of what it documents.

## Risks, ranked

### Blockers

**1. A pushing right sidebar already exists, and there is only one offset variable.** `#ai-rail` is already a dockable, drag-resizable, localStorage-persisted right panel; the reflow runs entirely through `--hims-ai-offset`, whose only two readers are `hims.css:175` and `:501`, and `hims.blade.php:660-661` writes it as a *variable alias* (`--hims-ai-offset: var(--hims-ai-w)`), not a resolved px value. A second panel that writes that variable destroys the aliasing and the resizer stops reflowing the page; one that does not write it overlays content with no reflow at all. *Mitigation:* do not add a second panel — rebuild inside `#ai-rail`. If two panels are genuinely required, first change `hims.css:175` and `:501` to `calc(var(--hims-ai-offset) + var(--hims-new-offset))` and keep every writer setting only its own variable.

**2. The planned sessions migration is a duplicate and aborts the documented dev reset.** `Schema::create('ai_chat_sessions')` already ran at `2026_08_06_000120:38`, and `session_id`/`seq` already exist at :53-54. A second create throws MySQL 1050 / SQLite "table already exists", and since there is no `Schema::hasTable()` guard convention in `database/migrations`, `php artisan migrate:fresh --seed` stops mid-run leaving a half-built `hims_v2`. *Mitigation:* write no table migration. The sessions layer is wired at `AiController.php:73-151` and `routes/web.php:359-366`; verify with `php artisan migrate:status` before adding anything.

**3. Adding a `session_id` FK strips the `role` enum CHECK from the sqlite test schema.** Confirmed empirically on this checkout (Laravel 13.22.0): SQLite's `compileForeign()` is a no-op (`vendor/.../Grammars/SQLiteGrammar.php:450-453`), so the add goes through `compileAlter()`'s `__temp__` rebuild (:353), which reconstructs columns from `BlueprintState::full_type_definition` (`BlueprintState.php:72`) — and SQLite reports an enum as plain `varchar` because `typeEnum()` emits a separate table-level CHECK (`SQLiteGrammar.php:873-880`). Probe: DDL went from `varchar check ("role" in ('user','ai')) not null` to `varchar not null`, after which inserting `'role' => 'system'` **succeeded**. MySQL still rejects it, so any "memory" work wanting a third role (system/summary turn) is green in CI and error 1265 in production. *Mitigation:* do not add the FK — this is exactly the trade-off `..._000120:17-26` documents and rejects. If a third role is needed, alter the enum on MySQL explicitly in its own migration and add an application-level guard, since the test connection will not enforce it.

**4. `AI_HISTORY_TURNS=0` — the documented "no memory" kill switch — makes history unlimited.** `config/services.php:54` says "Set AI_HISTORY_TURNS=0 for no memory"; `AbstractAiProvider.php:213-215` implements `array_slice($turns, -$this->historyTurns())`, and PHP's `-0` is `0`, so the whole array survives. Proven against the real class: 60 turns in, `history_turns=20` keeps 20, `history_turns=0` keeps all 60. Only `AI_HISTORY_CHARS=0` actually disables replay. This is the single lever an operator has when a thread blows up token cost or when review/patient text must stop leaving the hospital. *Mitigation:* one-line guard — `if ($this->historyTurns() < 1) { return []; }` before the slice — plus a unit test pinning `0 → 0 turns`, and fix the config comment. Do this before any UI work, because the sidebar rebuild makes replay the headline behaviour.

### High

**5. Every modal ignores the offset and two are wider than the remaining column.** `.hims-modal-backdrop` is `inset: 0; z-index: 1200` (`hims.css:1335-1344`) with `.hims-modal { margin: auto }` (1350-1361) — viewport-centred, reading no offset, painting over the rail (98). With the rail at `MAX_W = 620` on 1440px the content column is 560px, but `learning/assignments/_roster-modals.blade.php:5` is `max-width: 980px` and centres at 230–1210px, covering both rails; at the 1100px threshold the 220px column is covered entirely. Twenty-plus partials share this one rule. *Mitigation:* make the backdrop offset-aware (`right: var(--hims-ai-offset)` with matching `left`), or clamp `.hims-modal` to `min(<max-width>, calc(100vw - var(--hims-sidebar-w) - var(--hims-ai-offset) - 2rem))`. Test with the roster modal and `training/sessions/_create-modal.blade.php:19` (760px) at 1100px.

**6. The only desktop horizontal-scroll escape hatch is class-gated on the existing rail.** `.hims-card` is `overflow: hidden` (551-558) and `.hims-table th` is `white-space: nowrap` (597), so a narrowed table is silently *clipped* — no scrollbar. `.hims-table` has no desktop `min-width` (the 520px floor is inside `@media (max-width: 768px)`, :1293) and `.table-responsive` (912) is used in zero views. The single rescue is `hims.css:1258-1260`, keyed on `body.ai-rail-docked`, set only by `applyOffset()` (`hims.blade.php:663`). *Mitigation:* whatever docks must toggle that exact class, or the rule must be re-keyed to a docked-state-agnostic selector. Verify across the 35 files containing `.hims-table`.

**7. The push/overlay breakpoint is two numbers measured off different quantities.** JS uses `RAIL_PUSH_MIN = 1100` with `window.innerWidth < RAIL_PUSH_MIN` (`hims.blade.php:626, 648`), which *includes* the scrollbar; CSS uses `@media (max-width: 1099px)` (`hims.css:1243`), which excludes it — and HIMS pages routinely scroll (`min-height: calc(100vh - var(--hims-topbar-h))`, :503). At ~1110px outer with a 15px scrollbar, JS pushes the page and hides the backdrop while CSS simultaneously applies overlay mode: rail dropped 64px, `z-index: 100`, resizer `display: none` (1245-1251). *Mitigation:* derive one from the other — read the breakpoint from a custom property, or switch the JS test to `window.matchMedia('(max-width: 1099px)').matches` so both consult the same evaluator. Do not introduce a second breakpoint pair for a second panel.

**8. Width is clamped to a constant, never to the viewport, and replayed from localStorage on every load.** `applyWidth()` clamps to `MIN_W`/`MAX_W` with no `window.innerWidth` term (`hims.blade.php:627, 651-656`), and 667-668 restores the stored width unconditionally. Drag to 620 on a 2560px monitor, then sign in on an 1100px laptop (still push mode): 1100 − 260 − 620 = 220px, minus 56px of `.hims-main` padding = 164px usable, against nowrap 5-column tables. *Mitigation:* add a viewport term to the clamp (e.g. cap at `innerWidth - sidebarW - MIN_CONTENT`), re-clamp on `resize`, and re-clamp on restore rather than trusting the stored value.

**9. The sqlite table rebuild copies rows with FK checks off, so an FK is validated only in production.** `compileAlter()` wraps the `__temp__` copy in `PRAGMA foreign_keys = OFF/ON` (`SQLiteGrammar.php:356-360`), so dangling `session_id`s pass in CI; MySQL's `ALTER TABLE ... ADD FOREIGN KEY` validates existing rows, making a failed migration mid-deploy the first symptom. The one historical backfill ran once — `adoptLegacyMessages()` selects `whereNull('session_id')` at `..._000120:78-110`. Today it holds only because `AiController::query()` is the sole writer and always sets `session_id` (:211, :240) — a code invariant, unverifiable from the suite by construction. *Mitigation:* skip the FK (see blocker 3). If it is added anyway, run an orphan-count query against MySQL first and add a feature test asserting no `ai_chat_messages` row has a `session_id` absent from `ai_chat_sessions`.

**10. `seq` is an unguarded read-then-write, and a tie silently deletes turns from the model's memory.** `AiController.php:204-206` reads `max('seq')`, then inserts `++$seq` at :214 and :243 with no `DB::transaction` (contrast `destroySession()` :138 and `clearHistory()` :290), and the covering index is plain, not unique (`..._000120:56`). Two reachable paths: the Enter handler calls `sendQuery()` with no in-flight guard (`hims.blade.php:996-998`; `sendBtn.disabled` at :948 blocks only the button, against a 30s provider timeout), and `hims_ai_session` lives in localStorage so two tabs share one session by design. `transcript()` then orders `seq DESC, created_at DESC` (:503-504) and falls back to whole-second timestamps — the exact tie `seq` was added to fix (`..._000120:28-32`) — after which `sanitiseHistory()` "repairs" the scramble by popping the older duplicate (`AbstractAiProvider.php:174-178, 185-187`). Real turns vanish with no exception and no log. *(Flagged independently by the data and AI-memory lenses.)* *Mitigation:* wrap the read and both inserts in `DB::transaction`, add a unique index on `['session_id','seq']` in its own migration (after auditing for existing duplicates), and add a client-side in-flight guard. `AiChatSessionTest` has no concurrency case — add one.

**11. The three divergent wire shapes have zero test coverage.** `grep -rn "Http::fake" tests/` returns nothing and no test references `GeminiProvider`, `OpenAiProvider`, `AnthropicProvider` or `AiManager`; every AI test substitutes a fake `AiProvider` (`AiChatSessionTest.php:40-59`, `AiActionTest.php:55`, `GapAnalysisFeedbackTest.php:159`, `AiActionPlannerTest.php:48`, `HimsKnowledgeTest.php:168`), so no test ever builds a request body. The bodies really differ (Gemini `contents[]`/`model`/no system field, OpenAI leading system message, Anthropic top-level `system` and a `buildMessages()` that takes no `$scope` at :41-47, 82-96), and a role inversion, a lost turn, or a leading `ai` turn — which Anthropic rejects outright — ships green. *Mitigation:* three `Http::fake` tests, one per driver, asserting role mapping, turn order, system-block placement and that the first turn is `user`. This is the prerequisite for calling replay a feature.

**12. App-authored strings are replayed to the provider as the model's own voice.** `isSyntheticReply()` matches only `⚠️` and `AiAccessPolicy::REFUSAL_PREFIX` (`AbstractAiProvider.php:197-201`; policy constant at `AiAccessPolicy.php:43`), while `query()` persists every reply as role `'ai'` (:237-248) — including `AiActionExecutor`'s `'Done.'` (:115), `'Your role does not allow that action.'` (:52), `'That was rejected: …'` (:72), `'You are not allowed to do that.'` / `'That record could not be found.'` (:74-76), `'That could not be completed. Nothing was changed.'` (:80), `'I need that to be clearer — …'` (:148, :185), `'Tell me which record you mean and I will do it.'` (:178), plus `AiController`'s `'Cancelled — nothing was changed.'` (:317) and `'I can do that, but I need … first.'` (:339), and each driver's `?? 'No response generated.'`. This collides head-on with `HimsKnowledge.php:159-161`, which tells the model never to claim it created or changed anything unless told the action succeeded — while the transcript teaches it that its own voice says "Done." *Mitigation:* introduce a single filtered-prefix marker (or a `source` column / prefix constant) applied to every app-authored reply, and extend `isSyntheticReply()` to it. Decide deliberately whether executor outcomes should be replayed as *system* facts rather than dropped.

**13. Every message containing a common English verb costs two full round-trips.** `AiController.php:325-329` runs the `ACTION_VERBS` pre-filter — `add|new|set|change|update|make|log|record|move|mark|open|close` (:50-54), ordinary words — then calls `AiActionPlanner::plan()`, which issues its own `ask()` (`AiActionPlanner.php:47`); on a null plan (:331-333) the conversational `ask()` at :234 fires too. Both pay the whole system block, since every driver unconditionally prepends `systemContext()` (`OpenAiProvider.php:81`, `AnthropicProvider.php:44`, `GeminiProvider.php:95`) — measured 8,500 chars, of which 8,038 is `HimsKnowledge::appGuide()`, irrelevant to a JSON classification, plus the action catalogue (7,051 chars for admin, 756 for staff). The planner shares the same memoised singleton via DI (`AiActionPlanner.php:34`, `AppServiceProvider.php:19-28`), so there is no cheaper classifier. *Mitigation:* give the planner its own minimal system context (catalogue only, no app guide) and, if a cheap model is available, its own provider binding. Measure before/after; do not ship a session UI that multiplies threads on top of this.

**14. The history character budget excludes the system prompt, so the real per-turn ceiling is ~22,200 chars.** `capHistory()` sums only replayed turns (`AbstractAiProvider.php:217-223`); the system block is never counted, measured at 8,500 chars (+680 for a staff scope fragment, `AiAccessPolicy::scopeFor` :188-203). Add `history_chars` 12,000 (`config/services.php:62`) and the 1,000-char prompt cap (`AiController.php:186`) and one turn sends ~5,500 input tokens, re-sent every turn; `max_tokens` 1024 bounds generation only (`AbstractAiProvider.php:88-91`). Raising `AI_HISTORY_CHARS` to "remember more" moves the ceiling linearly with no awareness of the fixed ~9,200 chars in front of it. *Mitigation:* count the system block (and scope fragment) inside the same budget, or document a total-request ceiling next to the two knobs so the number an operator sets is the number that ships.

### Medium

**15. `down()` written the conventional way fails on sqlite.** `dropForeign('ai_chat_messages_session_id_foreign')` throws `RuntimeException('This database driver does not support dropping foreign keys by name.')` (`SQLiteGrammar.php:604-608`); only `dropForeign(['session_id'])` compiles. The repo convention is a literal inverse `down()` (`2026_08_16_000001:31-36`) and every migration is exercised by `RefreshDatabase` on sqlite. On MySQL there is an ordering trap too: `..._000120`'s own `down()` (:64-67) cannot drop `session_id` while an FK exists on it. *Mitigation:* if any FK is added, use the column-array form and re-run `migrate:rollback` on sqlite before committing.

**16. Wiring "New chat" to `POST /ai/sessions` writes permanent untitled rows nothing collects.** `storeSession()` inserts immediately with `title => null` (`AiController.php:90-95` → `createSession()` :465-483), and `sessions()` returns every row ordered `updated_at DESC, limit(100)` with no title or has-messages predicate (:75-79). The only deletes anywhere are `destroySession()` (:138-148) and `clearHistory()` (:290-293) — no empty-session cleanup in `app/` or `database/seeders/`. Today's JS avoids this deliberately: `startNewChat()` nulls the id client-side with a comment saying `query()` creates it on first send (`hims.blade.php:866-876`). The route is nonetheless live (`routes/web.php:362`) and used by `AiChatSessionTest.php:125`, so a new button will find it. *Mitigation:* keep the lazy-create pattern; if the button must POST, filter the list (`whereNotNull('title')` or an exists-messages predicate) and add pagination, because 100 empties hide real conversations.

**17. There is no "last spoken in" column — renaming reorders history.** `updateSession()` bumps `updated_at` on a pure rename (`AiController.php:117-122`), and both list reads sort by it (`sessions()` :77, `history()` :165, backed by the `['user_id','updated_at']` index at `..._000120:47`). `history()` also picks "the most recent conversation" by that column, so a rename changes which thread the rail resumes into; `storePending()` bumps it too (:413-417) while `clearPending()` deliberately does not (:420-425). *Mitigation:* add a nullable `last_message_at` touched only by `query()`'s message insert, backfill from `MAX(ai_chat_messages.created_at)` in a private migration method, and re-point both list reads and `history()` at it.

**18. Chat-history search is a leading-wildcard LIKE over the whole message table, per keystroke.** `GlobalSearchController::searchAiHistory()` correlates `ai_chat_messages` per session with `like '%term%'` inside a `whereExists` (:814-820) and applies `PER_SOURCE_LIMIT` only afterwards (:825); `message` is TEXT with no FULLTEXT index (`..._000090:11-19` indexes `user_id` only; `..._000120:56` adds `(session_id, seq)`). The layout fires it on a 220ms debounce per keystroke (`hims.blade.php:462-465`), and multiplying sessions per user multiplies the correlated scans. *Mitigation:* bound the search (recent N sessions, or a message-count/date window), lengthen the debounce, and add a MySQL FULLTEXT index with a gated test if prefix matching is acceptable — a leading wildcard can never use an index.

**19. A destructive-action exchange replays as a bare "confirm" → "Done." with the record stripped.** The confirmation is `⚠️`-prefixed (`AiController.php:366`), so `isSyntheticReply()` drops it *and* pops the question before it (`AbstractAiProvider.php:162-168`). Traced through the real sanitiser, `[user "delete user Bob", ai "⚠️ Delete user: **Bob** …", user "confirm", ai "Done."]` becomes exactly `[user "confirm", ai "Done."]` — so "what did you just remove?" is answered from a transcript with the subject excised, while the browser shows the full exchange (`loadConversation` appends every row unfiltered, `hims.blade.php:899-929`). *Mitigation:* persist the confirmation prompt with a distinct marker that keeps the *subject* in the replay while dropping the mechanics, or store the resolved record label on the turn so the pair sanitises to something truthful. Same marker work as risk 12.

**20. The `⚠️` discriminator is a duplicated bare literal driving four different decisions.** Its counterpart is a real constant (`AiAccessPolicy::REFUSAL_PREFIX`) but `⚠️` is inlined 8 times in `AbstractAiProvider.php`, 3–4 times in each driver, twice each in `NullAiProvider` and `AiActionPlanner`, once each in `AiController` and `CompetencyGapAnalysisService`. Four independent `str_starts_with` tests key off it: drop from replay (`AbstractAiProvider.php:199`), return null from `decodeJson` (:294), report "AI unavailable" on the gap-analysis screen (`CompetencyGapAnalysisService.php:818`), abort planning (`AiActionPlanner.php:86`). Reword one driver, add a provider that prefixes differently, or lose the U+FE0F variation selector (the comparison is byte-exact) and history stops filtering while gap analysis starts JSON-decoding an error string — silently. *Mitigation:* promote it to a constant alongside `REFUSAL_PREFIX`, have all four sites test the constant, and add a test that a driver failure string is filtered from replay.

**21. Legacy adopted messages have no deterministic order and mispair on replay.** `adoptLegacyMessages()` leaves `seq` NULL for adopted rows — "created_at is the only ordering information that exists for them" (`..._000120:102-104`) — while the same file's docblock explains that both halves of a turn share one whole-second `now()` (:28-32). Run through the real sanitiser, `[A1, Q1, A2, Q2]` yields `[user "Q1", ai "A2 answers Q2"]`: Q1 credited with Q2's answer, A1 and Q2 discarded. The "Earlier conversation" session is listed and selectable, so this fires on any deployment carrying pre-migration history. *Mitigation:* backfill `seq` for adopted rows in a new migration, ordering by `created_at, id` and pairing user-before-ai within each equal-timestamp group; or mark that session read-only so it never enters a replay.

**22. Gemini — the default provider — puts the system block last, behind the variable history.** `GeminiProvider.php:93-96` appends `systemContext()` to the final user turn because `system_instruction` is unsupported on older models; OpenAI and Anthropic put the identical block first as a fixed prefix. With replay as the headline feature, ~8,500 chars of unchanging text sits behind ~12,000 chars that change every turn, so the default provider structurally cannot form a stable cacheable prefix. *Mitigation:* if the configured Gemini model supports `system_instruction`, send it there and keep the concatenation only as a fallback for models that 400 on it; otherwise document the per-provider cost difference before raising `AI_HISTORY_CHARS`.

**23. `AI_HISTORY_TURNS` and `AI_HISTORY_CHARS` are absent from `.env.example`.** The neighbouring knobs are all documented (`AI_PROVIDER` :116, `AI_TEMPERATURE` :117, `AI_MAX_TOKENS` :118, `AI_TIMEOUT` :119, per-provider keys/models :122-137) but neither history variable appears; they are read only at `config/services.php:61-62`. The two settings that bound request size, per-turn cost and how much conversation leaves the hospital are invisible to whoever configures the box — and an operator who does find the comment gets unlimited replay (blocker 4). *Mitigation:* add both with their defaults and a one-line note, in the same commit as the `-0` fix.

**24. The "gap analysis must not receive chat history" invariant holds but nothing pins it.** `CompetencyGapAnalysisService` calls `ask($prompt)` with no history at :648 and :691, as does `AiActionPlanner.php:47`; drivers hold no state, and `AiProvider.php:17-22` explains why (memoised singletons shared by every consumer). But `GapAnalysisFeedbackTest`'s spy accepts `array $history = []` and records only `$prompt` (:159-165) with no assertion that history arrived empty, and no test covers the planner's call site — whereas `AiChatSessionTest` asserts `$spy->seenHistory` three times (:102, :111, :132). An edit threading history through a shared helper ships green. *Mitigation:* assert `$history === []` in the gap-analysis spy and add the equivalent for `AiActionPlanner`.

**25. The overlay backdrop sits below the topbar and left sidebar.** `#ai-rail-backdrop` is z 97 (`hims.css:1236-1242`) while `.hims-topbar` is 99 (:183) and `.hims-sidebar` is 100 (:58), and the sidebar only goes off-canvas at `max-width: 768px` (:1269-1272) — so between 769 and 1099px a user can navigate away through a supposedly modal rail. Inside the same query the rail is promoted to z 100 (:1248), *tying* the sidebar; it wins only because its include is at `hims.blade.php:282` versus the sidebar at :31, i.e. paint order by DOM order. *Mitigation:* raise the backdrop above 100 (and the rail above it) so overlay mode is actually modal, and break the tie explicitly rather than relying on include position — a new panel inserted elsewhere in `<body>` inherits the fragility.

**26. Topbar dropdowns are fixed-width and clamped against `100vw`, not their shrinking container.** `.search-dropdown` is 520px (`hims.css:366`) and `.notif-dropdown` 390px (:301), anchored `absolute; right: 0` in `.topbar-menu-wrap` (245-249) with `max-width: calc(100vw - 32px)` (:252) — but the topbar's own width is `100vw − sidebar − ai-offset` (174-175), so the clamp never fires. On 1366px with a 620px rail the topbar is 486px and the 520px panel overhangs its left edge, painting over the sidebar at z 1100; at the 1100px threshold both panels overflow by 300px and 170px. *Mitigation:* clamp against the real available width — `max-width: calc(100vw - var(--hims-sidebar-w) - var(--hims-ai-offset) - 32px)` — and shrink the declared widths to `min(520px, …)`.

**27. Only `margin-right`/`right` are transitioned, so a left-sidebar collapse would tear.** There is no desktop collapse today — no `collapsed` selector in `hims.css` or `hims.blade.php`, and `--hims-sidebar-w` is only ever read (:53, 174, 499). If one is added: `.hims-main` transitions only `margin-right .18s` (:504) and `.hims-topbar` only `right .18s` (:185), while `.hims-sidebar` has `all .18s` (:60) — the sidebar animates its width while the content snaps, a visible 180ms tear. The mobile path escapes this only via `translateX(-100%)` plus `margin-left: 0` behind a media query (1269-1281). *Mitigation:* if a collapse ships, add `margin-left`/`left` to those two transition lists in the same commit.

**28. `body.ai-resizing` names three selectors by hand.** `hims.css:508-510` suppresses transitions on `.hims-main`, `.hims-topbar` and `#ai-rail` only, set and cleared by the pointer handlers at `hims.blade.php:718-730`. Any new shell panel is absent from that list and will animate its `.18s` reflow on every `pointermove`, lagging the cursor — the exact failure the comment at :506-507 says the rule prevents. *Mitigation:* add any new resizable panel to the selector list, or restructure as `body.ai-resizing * { transition: none }` scoped to the shell elements.

**29. `departments/index.blade.php` hand-rolls a fixed modal inside the transformed wrapper.** `:109` renders `style="display:none;position:fixed;inset:0;…z-index:999;…"` with inline `onclick` at :13 and :130, outside `@push('modals')`, so it lands inside `<main>` inside `.animate-in`, whose `forwards` `translateY(0)` (`hims.css:1306-1313`) makes it the containing block — `inset: 0` resolves to `.hims-main`'s padding box, which carries `margin-right: var(--hims-ai-offset)`. With a sidebar docked it is confined to the narrowed column and its 480px panel (:110) cannot fit the 220px threshold column; `z-index: 999` also loses to `.topbar-dropdown` (1100). *Mitigation:* convert it to the documented contract — `@push('modals')`, `.hims-modal-backdrop`/`.hims-modal`, `data-modal-open`, `partials/modal-js` — before the docking work, so it is not the one page that breaks differently.

**30. Nothing guards against horizontal document overflow.** There is no `overflow` declaration on `html` or `body` anywhere in `hims.css` (`body` at 41-47 sets only font/background/margin/min-height); the existing rail depends on `visibility: hidden` precisely because a transform alone leaves a body scrollbar (comment at 999-1002). A new panel shipping closed with `translateX(100%)` and no `visibility: hidden` or zero width puts a horizontal scrollbar on all 46 shell views. Also note `#ai-rail { max-width: 100vw }` (:993) and the 480px `width: 100vw` (1253-1255) — `100vw` includes the scrollbar gutter, so the phone rule is already marginally over-wide. *Mitigation:* replicate the `visibility: hidden` pattern exactly for any new off-canvas element, and prefer `100%`/`100dvw` over `100vw` for full-bleed widths.

### Low

**31. Two document-level Escape handlers and an unconditional body-scroll lock cross over.** The layout registers a `keydown` handler closing sidebar, dropdowns and the overlaying rail (`hims.blade.php:563-573`), and `partials/modal-js.blade.php:64-68` registers a second, pushed to `@stack('scripts')` at :1005 so it runs after; neither stops propagation, so one Escape with a modal open in overlay mode closes the modal *and* the rail *and* the mobile drawer. Separately `modal-js` writes `document.body.style.overflow` directly (:31, :39), so whichever consumer closes last unlocks scroll and silently releases the other's lock. *Mitigation:* make the Escape handling a single prioritised chain (topmost layer only), and replace the direct style writes with a reference-counted lock helper.

**32. `query()` is the only chat write path with no transaction.** The user insert (`AiController.php:208-217`), the reply insert (:237-248) and the title/`updated_at` write (:252-254) are three separate statements, unlike `destroySession()` (:138) and `clearHistory()` (:290). Drivers catch `\Throwable` so `ask()` will not throw, but a `max_execution_time` kill against the 30s provider timeout commits the question and not the reply, leaving `title` null; the screen then shows an unanswered question while `sanitiseHistory()` pops that trailing turn out of the replay (`AbstractAiProvider.php:185-187`). *Mitigation:* single transaction around all three writes — the same change as risk 10.

**33. An unknown or garbled storage role defaults to assistant.** `$role = ($entry['role'] ?? '') === 'user' ? 'user' : 'ai';` (`AbstractAiProvider.php:150`) — a missing key, a truncated value or a future third role becomes text the model is told it said. The safe default runs the other way, and the one connection the suite runs on is the one with nothing enforcing the two legal values (see blocker 3). *Mitigation:* invert the default to `'user'`, or throw/log on an unrecognised role rather than silently attributing it to the model.

**34. 200 rows are read per send to feed a 20-turn cap.** `transcript()` fetches `HISTORY_LIMIT = 200` rows with full `message` text, maps and reverses them (`AiController.php:47, 498-513`), and `query()` calls it on every send (:202), after which `capHistory()` keeps 20 turns / 12,000 chars — so a few hundred KB is pulled from MySQL and ~90% discarded per message. The two limits live in different files with no relationship: lowering `AI_HISTORY_TURNS` does not reduce the read, and raising it past 200 silently caps at the controller constant. The same 200-row read also serves `sessionMessages()` (:98-106), where the full window *is* wanted. *(Flagged by both the data and AI-memory lenses.)* *Mitigation:* give the replay path its own smaller limit derived from `history_turns`, and leave `HISTORY_LIMIT` to `sessionMessages()`.
